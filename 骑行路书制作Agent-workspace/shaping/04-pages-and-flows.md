# 页面与流程

## 页面职责

1. **路书编辑器**：默认显示地图、搜索和「描述想骑的路线」入口。地图承载路线与点位，底部卡片承载路线名称、距离、预估累计爬升、时间、途经点和下一步操作。用户可展开对话或途经点列表。小屏优先保持地图可操作。
2. **地点确认与路线改动预览**：沿用编辑器内的底部卡片。显示同名地点选择、算路候选、里程与预估爬升差异、补给点和待核实条件。用户选点或应用候选后返回编辑状态。
3. **导出**：从当前路线打开导出面板，查看路线摘要并下载 GPX。面板提供顽鹿运动、行者和 iGPSPORT 的导入提示。失败后允许重试。

## 主流程

- 手动：进入编辑器 → 搜索或点地图选起终点 → 按需加途经点 → 按顺序算路 → 查看并调整 → 导出。
- Agent：输入需求 → 解析必经地点、环线等要求及里程、爬升和补给条件 → 搜索并在有歧义时确认地点 → 分段骑行算路、获取高程及校验条件 → 展示实际结果、偏差及未知条件 → 应用草稿 → 手动或对话微调 → 导出。
- 示例：用户把补给点移到河对岸后，系统重新算受影响的相邻路段并更新总里程。用户要求「控制在 45 公里以内」时，Agent 只将有里程依据且满足上限的候选标为符合，可展示接近方案并说明超出多少，让用户决定要不要放宽。

## 状态与处理

- 空白：提示用户选点或描述需求。缺少会影响算路的必要地点时，Agent 追问关键一项。
- 查询或算路中：显示正在搜索或规划。新一轮编辑优先，较慢返回的旧结果无法覆盖较新的路线。
- 无结果或路段不连通：指出具体地点或路段，允许改点、换候选或重试。保留此前完整版本及本次待编辑点位。若用户选择继续查看此前版本，界面明确展示对应版本。
- 偏好无法验证或满足：在候选上显示已满足、未满足或未验证的条件。严格要求无法确认时，按待核实处理。涉及明确冲突时，让用户改条件后再生成可应用方案。
- 高程不可用：显示「爬升暂无法核实」。保留地图和里程预览。有爬升硬上限时，任何缺少足够高程证据的候选都标为待核实。
- 补给：通过地点搜索取得门店名称和位置，按实际路线计算绕行距离。用户要求某个补给点必须经过时将其纳入途经点。营业状态和库存只有获得可信信息时才展示。
- 导出：生成中、成功、失败。正在重算的草稿要等完整有效才可导出。下载绑定界面上所选的完整版本。

## 数据与权限

- 规划需求记录用户原话、已确认的硬约束，以及允许权衡的偏好。距离「约 50 公里」与「最多 50 公里」按不同规则校验。
- 路线草稿包含有顺序的起终点与途经点、轨迹分段、计算距离与估时、估算累计爬升、坐标系、轨迹及高程来源和当前版本。用户选的点与 Agent 建议的点可追溯。预计时长按算路结果标记为预计。
- 模型负责理解需求、生成算路请求与解释候选。路径、坐标和可计算指标以地点搜索和路线服务结果为依据。多点算路检查相邻路段是否连续，偏好判断依赖相应的可用数据。
- 首版以个人草稿编辑与下载为主。建议默认私有，登录和持久化方式待技术方案确定。外部地图服务接收完成搜索或算路所需的地点与坐标。
