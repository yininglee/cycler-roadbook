# 产品定型

## 一句话定位

为全国骑友提供独立 Web 路书工具，用于出发前规划个人骑行路线。骑友可以直接在地图上选点，也可以描述里程、累计爬升、环线、必经点和补给需求，交由 Agent 查询地图信息、生成候选路线，再查看、调整和导出同一份路书。

## 目标用户与场景

- 全国骑友都可以作为路线创建者、编辑者和导出者。首版以个人使用为主，集合、补给等需求作为个人路书的规划条件。
- 全国是产品覆盖目标。验收使用多个地区和不同地形的样本，分别记录地点搜索、骑行路网和高程覆盖，包括港澳台的供应能力。
- 场景示例：用户说「从西湖文化广场出发，骑 50 公里左右，累计爬升不超过 400 米，经过一个补给点，最后回到出发点」。Agent 确认出发点、搜索候选补给点，为有顺序的地点算出骑行路段，并展示路线里程、预估累计爬升与需求偏差。用户在地图上换一个补给点，再导出当前路线。示例仅用于描述流程。
- 定位假设：用户愿意尝试这套工具，因为可以用一句话拿到地图上可检查的路线，并在同一处调整旅程和生成设备可用的文件。[待确认：用户现在使用的工具与切换成本]

## 产品形态与界面

- 首版为独立 Web 工具，界面参考 AI Cycler。建议让手机和桌面都能完成创建、编辑和下载，地图编辑器的交互以手机可用为基础。
- 采用附件中 AI Cycler 的浅灰背景、白色圆角卡片、黑色主按钮与蓝粉渐变的 AI 视觉提示。地图铺开，底部可收起卡片容纳路线摘要、编辑操作和对话入口。

## 高德接入判断

- **建议优先验证高德的底图、地点搜索和骑行算路能力。** 各地区的骑行算路覆盖以实际请求验收。 JS API 2.0 可显示地图与轨迹折线。Web 服务可搜索地点并查询骑行路线。高德骑行 API 2.0 支持起终点、备选方案和轨迹字段，其公开骑行参数未列途经点，因此顺序途经点建议采用相邻点分段算路，并检查拼接连续性。Agent 可以通过后端工具调用这些能力。高德也提供 MCP Server，可用于验证对话调用。 [地图折线](https://lbs.amap.com/api/javascript-api-v2/guide/amap-line/poly-line) · [地点搜索](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) · [骑行路线规划](https://lbs.amap.com/api/webservice/guide/api/newroute) · [高德 MCP](https://lbs.amap.com/api/mcp-server/)
- **先验证导出再定轨迹数据源。** 高德开放平台通用协议第 4.12、7.3 条涉及下载、存储和衍生使用等限制。应向高德确认本应用的轨迹保存、GPX 下载、第三方码表使用及商业场景的许可。高德使用 GCJ-02，官方不提供转回 GPS 坐标的接口。GPX 1.1 要求 WGS84。两项均明确后，再验证同一条实际路线在应用地图和目标设备上的轨迹对齐。若高德轨迹无法满足这些条件，评估明确许可导出、提供适用坐标的骑行路网或供应商，并按全国覆盖目标验证样本。 [高德开放平台协议](https://lbs.amap.com/pages/terms) · [高德坐标说明](https://lbs.amap.com/faq/advisory/others/39838) · [高德坐标转换说明](https://lbs.amap.com/faq/basis/location/1060046657) · [GPX 1.1 规范](https://www.topografix.com/GPX/1/1/)

- **首版爬升需要高程数据。** 高德公开骑行接口的返回字段包含距离和轨迹，未列海拔。优先验证一种沿轨迹批量取高程的方式。Copernicus GLO-30 可作为数据候选。它是约 30 米的地表模型，桥梁、隧道和高架需单独抽样校验。对完整且坐标对齐的轨迹，固定采样与平滑规则后累加正向高程变化，结果标为预估累计爬升。 [高德骑行接口](https://lbs.amap.com/api/webservice/guide/api/newroute) · [Copernicus DEM](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)
